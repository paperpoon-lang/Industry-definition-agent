## 一、总体判断

**v1.1 核心机制经日志确认全部落地且按设计工作**（按轮计数、双通道记录、fm_review_failed 补记、每轮采集）；团队报告的三个问题中，两个完全证实，一个需要细化。**其中"FM 永远判 productive"比团队报告的更严重**：它不是偏差问题，而是 FM 在缺乏判定依据的情况下照常给出判定——对字面重复的补搜轮（相同 query、相同返回量）依然判 productive，说明该信号在事实上不可信，v1.2 应把收益判定从 LLM 手里收回，交给机械信号。

## 二、断言验证（逐条对照日志）

今日日志共 9 个 trace：室内垂直农业 0076dfbd662a、钙钛矿 23735e21b6ac / 30716a7271b2 / 526f68577f8f / c340e7bcfac1 / 6ce1a108c18f、脑机接口 5246234916b6、细胞培养肉 92166ba3241d、固态电池 cc70e5c7ac62。全部 `mock: false`。

### 断言 1：FM 永远判 productive，low_yield 0 次触发 —— ✅ 证实，且比报告更严重

- 7 个完整运行的 `yield_history` 全部为 `[null, "productive", "productive"]`，无一例外。
- **决定性证据（室内垂直农业 0076dfbd662a）**：第 2 轮补搜的 query 与第 1 轮**逐字相同**（"室内垂直农业 国家标准 行业标准 术语定义" / "垂直农业 植物工厂 设施农业 温室农业 区别 边界"），返回结果数相同（5/5）、内容长度逐字节相同（6736/6732）——这是一轮**零新信息的重复搜索**，FM 依然判 `productive`。
- 推论：FM 的 yield 判定并非"偏松"，而是**没有真正检查搜索返回**。待团队确认的根因假设：FM 审查 prompt 可能根本没有喂入本轮搜索返回的内容（只见缺口列表），"productive" 对它而言是不可证伪的——它手里没有判 unproductive 所需的证据。若属实，这不是 prompt 措辞能修的问题，是输入设计问题。

### 断言 2：query 关键词空间穷尽（室内垂直农业 2→2→2 内容完全不变）—— ✅ 证实，且机制更清晰

- 室内垂直农业：第 2、3 轮 FM 的 data_gaps **逐字不变**；第 2 轮 suggested_queries 与第 1 轮**逐字相同**（重复执行），第 3 轮仅同义改写（"国家标准 GB 术语 定义"）。
- 钙钛矿 23735e21b6ac：第 3 轮 suggested_queries 与第 2 轮逐字相同（因预算耗尽未执行）。
- **新发现——重复 query 执行无防护**：重复 query 实际被**照常执行**了（`supplement_search_done` round 2 有完整返回记录），只是 `all_results` 字典按 query 文本去重覆盖了旧值。一轮重复 = 白烧 ~16s 搜索 + 一次 FM 审查，预算被无效消耗。执行前没有 query 文本去重闸门。
- 当前 dedup 语义还有记录偏差：`gap_record.queries_used`（字典键去重后 5 个）与 `supplement_queries: 4`（计数 4 个）对不上，排查时会产生困惑。

### 断言 3：残留缺口全是"信息不存在型" —— ◐ 需细化：实际有 4 类，去向各不相同

逐条分析 5 行业的终态 `remaining_gaps`，分四类：

| 类型 | 实例 | 真实属性 | 应去向 |
|------|------|---------|--------|
| **(i) 检索不可达** | GICS/NAICS 对钙钛矿/细胞培养肉/室内垂直农业的具体编码归属 | 新兴行业在标准分类中确无对应条目，信息不存在 | 接受为诚实终态（团队已确认的原则） |
| **(ii) 片段深度不足** | 固态电池电解质含量阈值——FM 第 3 轮已**点名 T/CSAE 434-2025 标准号**，但 Tavily 片段里没有具体参数 | 信息**存在**，片段太浅拿不到 | 阶段三非碎片化搜索源，**不是现在多搜几轮能解决的** |
| **(iii) 信源层级不足** | 细胞培养肉"P0 级一手来源（FDA/USDA 联合监管文件原文、SFA 审批文件）" | 信息存在但 Tavily 返回以媒体报道为主 | 阶段三搜索源升级 |
| **(iv) 分析任务误报** | 脑机接口"维度选择/放弃的理由说明"、"结构性特征与热点区分"；细胞培养肉"结构性特征提炼" | **这不是信息缺口**——是报告自身的推理义务（Hard Rule R2、自检 C3），搜索永远闭不了 | 从 data_gaps 中剔除，归 Step 2/4/5 管 |

**(iv) 类是本次实测暴露的新失效模式：FM 审查范围越界**——把报告内部的推理义务误报为外部信息缺口。脑机接口 run 里 FM 甚至为此生成"脑机接口 行业定义 维度选择 方法论"这类 query——不会有任何网页解释"我们的报告为什么选了这些维度"。这类缺口占比不小（脑机接口 2/2、细胞培养肉 1/4），若不清除，补搜循环会永远为不可能闭合的目标空转。

## 四、风险矩阵

| 级别 | 风险 | 说明 | 建议应对 |
|------|------|------|---------|
| **P1** | `last_round_yield` 信号不可信 | 对零新信息轮照样判 productive；该信号当前不能作为循环依据，留着还会污染 yield_history 数据 | v1.2 改用机械信号为主判据（见下）；FM 自评降级为参考或要求举证 |
| **P1** | FM 审查范围越界（iv 类误报） | 推理义务被当信息缺口，补搜为空转目标烧钱，且残留缺口清单误导读者 | v1.2 prompt 收敛 + gap_type 分类（见下） |
| **P2** | 重复 query 无防护执行 | 一轮重复白烧 ~16s + 一次 FM 审查预算 | 执行前去重 + 新 stop_reason（见下） |
| **P3** | `queries_used` 与 `supplement_queries` 计数口径不一致 | 字典去重 vs 执行计数，排查困惑 | 统一口径或改名区分 |
| **P3** | fm_review_failed 时 remaining_gaps 语义 | `[]` 易被误读为"无缺口" | 置 null/unknown |

## 五、v1.2 建议方向（三项，均在阶段二范围内，不依赖阶段三）

### 5.1 收益判定改机械信号（取代 FM 自评）

利用步骤 2 已落地的采集数据，零 LLM 成本、可单测：

```python
# 每轮补搜后、FM 审查前判定：
round_queries = queries_this_round
if all(q in queries_used before this round for q in round_queries):
    yield = "unproductive"          # 全部重复
elif all(results_per_query[q] == 0 for q in round_queries):
    yield = "unproductive"          # 全部零返回
# 可选第三信号：与历史返回内容 hash 重叠度（content_lengths 完全相同即高度可疑）
```

连续 2 轮 unproductive 止损的逻辑不变，只是信号来源换掉。FM 的 `last_round_yield` 字段若保留，应改为**要求举证**：判 productive 必须引用"哪条新内容推进了哪个缺口"，引不出证据的 productive 按 unproductive 处理（这同时能检验根因假设——如果 FM 根本看不到搜索内容，它必然举不出证）。

### 5.2 新增 `query_space_exhausted` stop_reason + 执行前去重

- 执行前过滤与历史重复的 query；
- 若 FM 本轮 suggested_queries **全部**为已试 query → 视为"未试动作枚举为空"（Tavily 时代对白名单穷尽的近似），记 `stop_reason: query_space_exhausted` 停止；
- FM prompt 中传入已试 query 清单并禁止重复，要求换角度（如：换英文、换标准号/机构名定点搜——固态电池 run 证明 FM 有能力生成"T/CSAE 434-2025"这种带证据的精准 query，应鼓励）。

### 5.3 FM 审查范围收敛 + per-gap 类型标注

- prompt 明确：**只报告可通过搜索补全的事实性信息缺口**；维度选择理由、结构性特征提炼等是报告自身推理义务（R2/C3），不属于 data_gaps；
- schema 中每个缺口加 `gap_type` 标注（`not_found / snippet_too_shallow / source_tier / reasoning_task`），终态记录按类型路由：(i) 诚实声明、(ii)(iii) 标记"待阶段三搜索源"、(iv) 移出 data_gaps 转 Step 5 检查项；
- 报告尾部的缺口声明随类型给出不同的人读文案，读者能区分"这信息不存在"和"这信息需要更深的搜索源"。

### 5.4 明确不做的

(ii)(iii) 类的真正解法（非碎片化搜索源、一手信源接入）属阶段三，v1.2 只做好分类与标记，不在 Tavily 上继续加轮次硬磕。
