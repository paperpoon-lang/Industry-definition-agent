## 二、v1.2 数据的关键解读

### 2.1 根因假设被证实：FM 的判定能力从来不是问题

v1.1 评估中的核心假设是："FM 永远判 productive 不是偏松，而是手里没有判 unproductive 所需的证据——输入设计问题。" v1.2 数据直接证实了这一点：

- 加入举证机制 + seen_queries 注入后，3/5 行业出现 unproductive 判定，且室内垂直农业/脑机接口能举出具体证据；
- (iv) 类误报（推理义务混入 data_gaps）100% 剔除，说明 prompt 收敛生效。

**推论**：v1.1 风险矩阵中 P1 级"last_round_yield 信号不可信"已被 v1.2 实质性修复。"让 FM 自评参与止损"在 v1.1 时是危险的，在 v1.3 时是合理的——这是本次评估最重要的立场更新。

### 2.2 现成的反事实证据：钙钛矿 run

钙钛矿 `yield_history: [None, unprod, unprod]`，stop_reason 却是 budget_exhausted。这意味着：**FM 已连续两轮判 unproductive，机械信号未同步判出，止损权被机械信号独占导致 low_yield 未触发。** 这不是抽象矛盾，是直接的反事实证据——若 v1.3 让 FM 参与止损，3/5 的 run 会立即从 budget_exhausted 翻转为 low_yield。stop_reason 分布维度（权重 30%，当前 C）大概率显著改善。

### 2.3 但也因此：过校正风险是真实的

正因为翻转会立竿见影，v1.3 必须防范新的失效模式：**FM 误判 unproductive 导致过早止损**（v1.1 是"永不止损"，v1.3 可能摆向"轻易止损"）。5 行业样本不足以排除 FM"为了合规而编证据"或对新行业过度悲观的可能。

## 三、对 v1.3 三项候选措施的评议

### 3.1 FM 自评参与止损 —— ✅ 同意，附两个约束

**约束 1：不做"FM 一票否决"，举证非空才生效。**
FM 判 unproductive 计入 consecutive_unproductive，但要求举证字段非空；举不出证的 unproductive 降权（不计入或计 0.5）。这是防静默降级/防编造证据的最低成本闸门，与 v1.2 举证机制自然衔接。

**约束 2：举证可验证化（假举证防线）。**
举证非空只能防"不举证"，防不了"假举证"（FM 为合规编造证据）。解法：prompt 要求举证时**逐字引用**本轮返回内容中的片段或标识符（标准号、编码、数据值），由机械校验器将引用字符串与本轮 `supplement_search_done` 原始返回做子串匹配，匹配失败的 unproductive 不计入 consecutive。零 LLM 成本、确定性、可单测。v1.2 的举证实例（NAICS 1114、YY/T 1987-2025）本就是标识符式，几乎不改变 FM 输出习惯。

~~约束 2（原）：确认 low_yield 与 budget_exhausted 判定顺序~~ —— **已由 Trae 于 2026-08-15 证伪**：代码 L647-665 显示 low_yield 检查先于 budget 检查，顺序正确，零触发根因确为机械信号 5/5 判 productive。该 P1 风险关闭。

### 3.2 步骤 4（注入上一轮搜索摘要）—— ◐ 降级为可选实验项

- 其目标（提高 FM 判定准确率）与 v1.2 举证机制重叠，边际收益待验证；
- 有 token 成本，v1.2 刚降本 3%（¥1.1711→¥1.1345），不宜轻易吃回；
- 若实施，**注入结构化摘要（query + 结果数 + 内容指纹），不注入原文**，控制 token 膨胀。

### 3.3 内容指纹比对 —— ✅ 建议从"或"升级为"并行"

"不同 query 返回相似内容"是 FM 和现有机械信号（query 去重/零返回）都覆盖不了的失效模式。指纹比对零 LLM 成本、可单测；v1.2 已在采集 content_lengths，加跨轮内容 hash 是顺手的事。它是三条措施中**唯一不依赖 LLM 判断可信度**的，对冲了 3.1 的过校正风险。

### 3.4 必须新增：止损正确性审计维度

一旦 low_yield 可能真实触发，评估框架要回答"触发得对不对"。建议 v1.3 实测新增维度：**每次 low_yield 触发时人工核对 remaining_gaps 是否确属 (i)(ii)(iii) 类不可闭合缺口**。现有五维框架抓不住"过早止损"，5 行业样本下一次误判就值 20% 的假阳性率。
