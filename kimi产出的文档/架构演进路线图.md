**核心设计原则（贯穿所有阶段）**：

1. **接口向前兼容**：v3 打桩的接口（`call_with_retry` → `CircuitBreaker.call`、`SimpleLogger` → `SessionEventLog`、`save_checkpoint` / `try_resume` → `CheckpointManager`）在升级时只换实现不换签名
2. **质量组件不减**：Evaluator 独立化、Context Builder 分层、搜索并行压缩——这三个从 v3 起就完整实现，后续阶段只增强不替换
3. **基础设施逐步完善**：从 v3 的"print 日志"到生产的"审计管道"，从 v3 的"retry"到生产的"完整 Circuit Breaker"，逐步升级

## 二、演进路径：四个阶段

### 阶段一：Demo MVP（v3，现在）

**目标**：跑一次出高质量报告，给人看不尴尬。

| 维度 | 状态 |
|---|---|
| **代码量** | ~700 行 Python |
| **运行方式** | `python frost_agent.py "行业名称"` |
| **Harness 组件** | 6 个完整做 + 5 个打桩 + 3 个不做 |
| **Environment** | Credential Vault (最小实现) |
| **并发** | 无（单次 CLI 运行） |
| **持久化** | Checkpoint (save + load，极简) |
| **审计** | print + 可选文件 |
| **成本** | 单一模型，无优化 |

**验收标准**：
- [ ] `python frost_agent.py "低空经济物流"` 稳定产出报告（3/3 次成功）
- [ ] Step 5 自检 C1-C5 逐项有 PASS/FAIL
- [ ] 报告不含竞争排名/市场规模/投资建议
- [ ] 崩溃后可恢复（kill -9 后重跑）
- [ ] Step 1 搜索 < 10 秒

---

### 阶段二：内部试用（分析师使用）

**触发条件**：Demo 验收通过，行业定义分析师开始试用。

**新增需求**：
- 分析师一天可能跑 5-10 个行业，不能每次重新搜索
- 需要看到运行进度和 token 消耗
- 方法论可能需要调整（如新增规则 R6），不改代码就能生效
- 需要 Web UI（分析师不习惯命令行）

**升级项**：

| 组件 | v3 状态 | 阶段二升级 | 工作量 |
|---|---|---|---|
| **Persistent Memory** | 无 | SQLite 存储行业知识，相似行业复用历史经验 | 2-3 天 |
| **Session Event Log** | print | JSONL 结构化 + 查询接口（按 step/type 过滤） | 1 天 |
| **Token Audit** | StepOutput 字段 | 持久化审计日志 + 单次运行成本报表 | 0.5 天 |
| **Checkpoint** | save/load JSON | 多版本管理 + 过期清理 | 0.5 天 |
| **methodology/ 拆分** | 单文件 | 拆成 8 模块 + `_meta.yaml` + 版本校验 | 1 天 |
| **Circuit Breaker** | call_with_retry | 完整状态机（CLOSED/OPEN/HALF_OPEN）+ 按操作类型分组 | 1 天 |
| **Web UI** | 无 | Streamlit/Gradio：输入行业名 → 显示进度 → 展示报告 | 2-3 天 |
| **Sprint Contract** | prompt 内嵌 | 自动化协商（LLM 生成验收标准） | 1 天 |

**预计工作量**：~2 周（1 人）

---

### 阶段三：批量处理（生产化前奏）

**触发条件**：分析师反馈良好，需要批量处理（如一次跑 50 个行业）。

**新增需求**：
- 批量输入（CSV/Excel 行业列表）
- 成本控制（不能 50 个行业烧掉几千美元）
- 结果批量导出
- API 接口供其他系统调用

**升级项**：

| 组件 | 阶段二状态 | 阶段三升级 | 工作量 |
|---|---|---|---|
| **Model Router** | 单一模型 | 按步骤选模型（搜索用 flash，生成用 sonnet）+ fallback 降级链 | 2 天 |
| **Prompt Cache** | 无 | 静态 System Prompt 前缀缓存对齐，降低 40-80% 成本 | 1 天 |
| **Rate Limiter** | 无 | API 调用频率限制，防止触发供应商限流 | 0.5 天 |
| **API Server** | 无 | FastAPI：POST /analyze（单个行业）+ POST /batch（批量） | 2-3 天 |
| **Evaluator-Optimizer 闭环** | 无（人工审查后修）| 最多 3 轮自动修正（保留人工 override） | 2 天 |
| **Output Safety** | 最小实现 | 完整 workspace 边界检查 + 版本命名（自动追加时间戳） | 0.5 天 |
| **Harness Ablation** | 无 | 可开关单个 harness 组件，对比质量/成本 | 1 天 |

**预计工作量**：~2-3 周（1 人）

---

### 阶段四：生产级（行业定义内部工具）

**触发条件**：成为分析师日常工作流的一部分，需要 7×24 稳定运行。

**新增需求**：
- 多用户并发（多个分析师同时使用）
- 完整审计链（谁、什么时候、分析了什么行业、消耗多少 token）
- 成本预算和告警
- 方法论版本管理（灰度发布新方法论）
- 可选：Human-in-the-Loop（高风险行业人工确认）

**升级项**：

| 组件 | 阶段三状态 | 阶段四升级 | 工作量 |
|---|---|---|---|
| **Session Event Log** | JSONL | 接入审计管道（如 ELK/ClickHouse），支持跨会话查询 | 3-5 天 |
| **Credential Vault** | .env | 加密存储（如 HashiCorp Vault），支持多环境（dev/staging/prod） | 2-3 天 |
| **Human-in-the-Loop** | 无 | Step 5 自检失败后暂停，等待人工确认再继续 | 2-3 天 |
| **LangGraph 集成** | 无 | 若需要复杂编排（条件分支、子图、断点），用 LangGraph 替换 Orchestrator | 5-7 天 |
| **Docker Sandbox** | 无 | 可选：若未来引入代码执行能力，用 Docker 隔离 | 3-5 天 |
| **方法论文档版本管理** | 拆分 + 版本校验 | 灰度发布（部分用户用 v2.1，部分用 v2.2） | 3-5 天 |
| **Persistent Memory** | SQLite | 接入向量数据库（如 Chroma），支持语义相似行业搜索 | 3-5 天 |

**预计工作量**：~1 个月（1-2 人）

## 三、各阶段接口兼容性保证

v3 打桩的 5 个接口，在每个阶段的升级方式：

### 3.1 `call_with_retry()` → `CircuitBreaker.call()`

```python
# v3 (打桩)
async def call_with_retry(fn, max_retries=2):
    for attempt in range(max_retries + 1):
        try:
            return await fn()
        except Exception:
            if attempt == max_retries: raise
            await asyncio.sleep(2 ** attempt)

# 阶段二 (完整实现) —— 签名兼容
class CircuitBreaker:
    async def call(self, fn, *args, **kwargs):  # 签名兼容
        # 完整状态机实现
        ...

# 调用方不需要改
result = await call_with_retry(lambda: step_fn(state))   # v3
result = await breaker.call(step_fn, state)               # 阶段二，等效
```

### 3.2 `SimpleLogger` → `SessionEventLog`

```python
# v3 (打桩)
class SimpleLogger:
    def log(self, event_type: str, data: dict):
        print(f"[{event_type}] {data}")

# 阶段二 (完整实现) —— 签名兼容
class SessionEventLog:
    def log(self, event_type: str, data: dict):      # 签名相同
        # JSONL 结构化写入
        ...

    def query(self, event_type=None, step_id=None):   # 新增方法
        ...

    def recover_state(self) -> ReportState | None:    # 新增方法
        ...

# 调用方：阶段二可以直接替换 SimpleLogger，不需要改任何 log() 调用
```

### 3.3 `save_checkpoint` / `try_resume` → `CheckpointManager`

```python
# v3 (打桩)
def save_checkpoint(state: ReportState, step_id: str): ...
def try_resume(industry_name: str) -> ReportState | None: ...

# 阶段二 (完整实现) —— 签名兼容
class CheckpointManager:
    def save(self, state: ReportState, step_id: str): ...       # 兼容
    def load(self, industry_name: str) -> ReportState | None: ... # 兼容
    def list_versions(self, industry_name: str) -> list: ...     # 新增
    def cleanup_old(self, days=7): ...                           # 新增

# 调用方：阶段二可以直接用 CheckpointManager.save() 替换 save_checkpoint()
```

### 3.4 Sprint Contract (prompt 内嵌) → `SprintContract` 对象

```python

STEP_PROMPTS = {"1_info_collection": "...\n验收标准：找到至少 1 个 P0 来源"}

# 阶段二 (对象化) —— 不破坏现有代码
class SprintContract:
    @staticmethod
    async def negotiate(step_id: str, state: ReportState) -> "SprintContract":
        # 新增：LLM 自动生成验收标准
        ...

# 阶段二可以在 Orchestrator 中新增可选逻辑，不影响 v3 的 prompt 内嵌方式
```

### 3.5 Token Audit (StepOutput 字段) → `TokenAudit`

```python
# v3 (字段)
class StepOutput:
    token_usage: dict | None = None

# 阶段二 (类) —— 不破坏现有代码
class TokenAudit:
    def record(self, step_id, model, input_tokens, output_tokens): ...
    def report(self) -> dict: ...  # 生成成本报表
    # StepOutput.token_usage 字段保留，TokenAudit 读取它
```

## 四、关键决策记录

| 决策 | v3 选择 | 未来可能变更 |
|---|---|---|
| **单 Agent vs 多 Agent** | 单 Agent | 阶段四可升级为 Planner+Generator+Evaluator 三 Agent |
| **状态管理** | ReportState 内存对象 | 阶段三可评估 LangGraph StateGraph |
| **搜索工具** | Tavily API | 阶段三可接入多个搜索源（Tavily + Serper + 自建） |
| **模型** | 单一模型 | 阶段二开始 Model Router，阶段三多模型降级 |
| **方法论存储** | 单文件 markdown | 阶段二拆分为模块 + `_meta.yaml` |
| **持久化** | Checkpoint JSON | 阶段二 SQLite，阶段四向量数据库 |
| **审计** | print | 阶段二 JSONL，阶段四审计管道 |

## 五、风险与应对

| 风险 | 阶段 | 应对措施 |
|---|---|---|
| Demo 不稳定（API 超时/限流） | v3 | `call_with_retry` + 搜索全失败降级 |
| 方法论理解偏差（LLM 没按规则执行） | v3 | Independent Evaluator 拦截 |
| 成本超预算（阶段三批量处理） | 阶段三 | Model Router + Token Audit + 预算上限 |
| 方法论频繁变更 | 阶段二 | 外部加载 + 版本校验，不改代码 |
| 多用户并发冲突 | 阶段四 | Checkpoint 按用户隔离 + SQLite 事务 |
