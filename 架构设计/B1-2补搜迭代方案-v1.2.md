## 二、设计目标

**用机械信号解决FM自评不可信问题，用范围收敛解决FM越界误报问题，用去重解决query空间穷尽时的预算浪费。**

- 收益判定从"LLM自评"升级为"机械信号为主 + LLM举证为辅"
- FM审查范围从"所有缺口"收敛为"仅事实性信息缺口"，per-gap类型标注路由不同去向
- 补搜执行前query去重，新增 `query_space_exhausted` stop_reason
- **接受"(i)类检索不可达"为诚实终态**，(ii)(iii)类标记"待阶段三"，(iv)类移出data_gaps

## 三、评估框架（规则3：先定义框架再展开）

| 维度 | 权重 | 评级标准 | 信息来源可信度 |
|------|------|---------|---------------|
| stop_reason 分布合理性 | 30% | A: gaps_closed/query_space_exhausted/low_yield 至少出现2种；B: budget_exhausted仍占主体但非100%；C: 仍100%单一化；D: 出现新异常stop_reason | ★★★★★ 一手实测 |
| 缺口类型路由正确性 | 25% | A: (iv)类误报100%剔除；B: (iv)类占比下降>50%；C: (iv)类仍存在；D: (i)类被误剔除 | ★★★★☆ 同行评议+实测 |
| 机械信号有效性 | 20% | A: low_yield至少触发1次且可复现；B: low_yield触发但不稳定；C: 仍0次触发；D: 机械信号误判 | ★★★★★ 一手实测 |
| 预算节约 | 15% | A: 重复query 0次执行；B: 重复query≤1次；C: 重复query仍多次执行 | ★★★★★ 一手实测 |
| 成本/延迟可控 | 10% | A: 单行业成本<¥0.30、搜索阶段<150s；B: 成本<¥0.40或<200s；C: 超出；D: 超出且无止损 | ★★★★★ 一手实测 |

**总分计算规则**（architecture-critic P0-3 修复）：

采用数值映射：A=4, B=3, C=2, D=1。加权平均后：
- 加权平均 ≥ 3.5 → A 级（可进入阶段三评估）
- 加权平均 ≥ 3.0 → B 级（可交付编码）
- 加权平均 < 3.0 → 不可交付

**一票否决条款**：任一维度为 D 级则不可交付（防止 D 级风险被加权平均稀释）。

**示例**：5维度分别得 A/B/B/C/B → 加权平均 = 0.3×4 + 0.25×3 + 0.2×3 + 0.15×2 + 0.1×3 = 1.2+0.75+0.6+0.3+0.3 = 3.15 → B 级（可交付）。

| 位置 | 当前代码 | 改为 |

```python
# L534-540 新增
# architecture-critic P1-5 修复：去重前strip()规范化，避免首尾空格/多余空格导致语义相同query未去重
seen_queries: set[str] = {q.strip() for q in all_results.keys()}  # 首轮3个query入集合（规范化）

# L607-613 改为
remaining_budget = MAX_TOTAL_QUERIES - queries_used
# 执行前去重：过滤已见query（strip规范化）
new_queries = [q for q in suggested_queries if q.strip() not in seen_queries]
queries_to_search = new_queries[:remaining_budget]

if not queries_to_search:
    if not new_queries:
        stop_reason = "query_space_exhausted"  # FM建议的全部query已试过（含同义改写但严格相等判定）
        print(f"  [补搜] 第 {round_num + 1} 轮 FM 建议的 query 全部已试过，关键词空间穷尽")
    else:
        stop_reason = "budget_exhausted"  # 有新query但预算用尽
    break

# 执行前更新 seen_queries（规范化）
seen_queries.update(q.strip() for q in queries_to_search)
```

> **architecture-critic P1-2 说明**：`query_space_exhausted` 的触发条件是"严格相等去重后为空"。FM做同义改写（如"国家标准"→"GB标准"）时不会触发此stop_reason，循环会继续到budget_exhausted。这是已知局限——完整的语义去重属阶段三（embedding相似度）。v1.2通过步骤3 prompt注入`seen_queries_list`清单 + 要求FM"换角度（换英文/标准号/机构名）"来部分缓解，但无法完全阻止同义改写。`query_space_exhausted`主要捕获"FM完全照抄历史query"的极端场景。

**stop_reason 总表（v1.2 更新）**：

| stop_reason | 含义 | 触发条件 | 状态 |
|-------------|------|---------|------|
| `gaps_closed` | 缺口全部闭合 | FM返回data_gaps为空 | v1.1保留 |
| `low_yield` | 期望收益止损 | 机械信号连续2轮unproductive（步骤2生效后） | v1.2改信号源 |
| `budget_exhausted` | 预算用尽 | 补搜轮数>=MAX_SUPPLEMENT_ROUNDS 或 有新query但预算用尽 | v1.1保留 |
| `query_space_exhausted` | **关键词空间穷尽** | FM建议的全部query已试过（去重后为空） | **v1.2新增** |
| `fm_review_failed` | FM审查失败 | timeout/parse_error/exception | v1.1保留 |
| `no_suggested_queries` | FM未生成补搜关键词 | suggested_queries为空 | v1.1保留 |

**工作量**：<1h（纯逻辑改动，无LLM/prompt改动）
**优先级**：P0
**风险**：极低。去重是纯过滤逻辑，不影响现有stop_reason触发。唯一注意：`seen_queries` 初始化要包含首轮3个query，避免首轮补搜query与首轮静态query重复。

### 步骤2（P1）：机械信号收益判定 + FM自评降级为参考并要求举证

**改动文件**：`demo2/frost_agent.py`（[L534-540](file:///Users/paper/trae_project/行业定义agent/demo2/frost_agent.py#L534-540) 初始化 + [L582-591](file:///Users/paper/trae_project/行业定义agent/demo2/frost_agent.py#L582-591) 信号B止损 + [L123-163](file:///Users/paper/trae_project/行业定义agent/demo2/frost_agent.py#L123-163) FM_REVIEW_PROMPT）

**设计原则**：机械信号为主判据（零LLM成本、可单测），FM自评降级为参考并要求举证。

**机械信号判定逻辑**（每轮补搜后、FM审查前判定）：

> **architecture-critic P0-2 修复**：原方案信号3（content_lengths与上一轮逐字节相同）是死代码——步骤1去重已保证相同query不重复执行，不同query的字典键不同则比较必为False。删除信号3，承认机械信号只覆盖"全部重复+全部零返回"两种场景。覆盖局限由步骤2的FM举证机制补充。

```python
def _mechanical_yield_judgment(
    queries_this_round: list[str],
    results_per_query: dict[str, int],
    seen_queries: set[str],
) -> str:
    """机械信号收益判定。返回 'productive' | 'unproductive'。

    判定规则（按优先级）：
    1. 全部重复query → unproductive（步骤1去重后应0次触发，作安全网）
    2. 全部零返回 → unproductive
    3. 其他 → productive（保守，不轻易误判）

    覆盖局限：无法捕获"不同query返回相似内容"场景（如FM同义改写query）。
    该场景由步骤2 FM举证机制补充（要求productive必须引用具体证据）。
    """
    # 信号1：全部重复（步骤1去重后理论上不会发生，作安全网）
    if all(q in seen_queries for q in queries_this_round):
        return "unproductive"

    # 信号2：全部零返回
    if all(results_per_query.get(q, 0) == 0 for q in queries_this_round):
        return "unproductive"

    return "productive"
```

**不采纳 Kimi 的"内容hash重叠度"作主判据**：理由——hash计算增加复杂度，且不同query返回相似内容不等于无收益（可能是同一缺口的不同角度信息）。改由FM举证机制（步骤2）补充覆盖"同义改写但无实质进展"场景。

**机械信号与FM自评的仲裁规则**（architecture-critic P1-3 修复）：

- **机械信号独占止损权**：`consecutive_unproductive` 计数只由机械信号驱动，FM自评不参与止损决策
- **FM自评改要求举证**：FM返回 `last_round_yield="productive"` 时必须同时返回 `yield_evidence` 字段（引用"哪条新内容推进了哪个缺口"）
- **举证失败处理**：若FM返回 `last_round_yield="productive"` 但 `yield_evidence` 为空字符串，记入 `yield_history` 的值为 `"unproductive_no_evidence"`（保留FM原始判断的痕迹，便于离线分析），但**不参与** `consecutive_unproductive` 计数
- **双轨记录**：`yield_history` 记录FM原始判断（含 `unproductive_no_evidence` 标记），`mechanical_yield_history` 记录机械信号判断，两通道分离供离线对比

```python
# FM 自评举证处理（在FM结果解析后）
```

**reasoning_task 类型取舍说明**（architecture-critic P1-1 修复）：

Kimi [§5.3](file:///Users/paper/trae_project/行业定义agent/kimi产出的文档/B1-2-v1.1实测验证评估.md) 建议 4 种 gap_type 含 `reasoning_task`。v1.2 **采纳**此类型，但设计为"FM内部识别后从data_gaps中排除"（不写入返回的data_gaps列表），而非"写入data_gaps并标注reasoning_task"。

**理由**：
- 若reasoning_task缺口写入data_gaps → 仍会进入补搜循环 → 为不可能闭合目标空转（与v1.1问题相同）
- 若reasoning_task缺口从data_gaps排除 → 不进入补搜循环 → 直接消除(iv)类误报的预算浪费
- 风险：FM可能不遵守排除指令，仍把推理义务写入data_gaps → 此时归入untyped，detail仍显示缺口内容（P0-1 zip_longest兜底保证不丢失）
