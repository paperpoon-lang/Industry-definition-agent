## 三、v1.3 方案：三信号并联止损

### 3.0 总体流程

```
补搜第N轮执行后（即时信号，不依赖FM）：
  信号2（指纹）：本轮有效结果的fingerprints 与 全历史集合 比对，重叠率≥阈值 → unproductive
  信号3（机械）：沿用v1.2 _mechanical_yield_judgment（全部重复/全部零返回）
  → 存入 round_partial_signals（1-based补搜轮编号）

第N+1轮FM审查后（组合判定第N轮收益，插入位置：gaps_closed检查后、budget检查前）：
  信号1（FM自评，双向举证闸门）：
    productive + 举证有效 → productive
    productive + 举证无效 → unproductive_no_evidence（计入triggered）
    unproductive + 举证有效（说明为何没用）→ unproductive（计入triggered）
    unproductive + 举证无效 → None（降权断链：无法确认，不触发也不重置）
    null/缺失 → None（断链）
  组合判定：fm OR fingerprint OR mechanical 任一unproductive → 本轮无收益
  连续2轮无收益 → stop_reason=low_yield（逐轮记录触发信号组合）
```

### 3.1 信号1：FM自评 + 结构化双向举证

**FM prompt 中 yield_evidence 格式**：

```json
"yield_evidence": [
  {"query_index": 0, "gap_index": 1, "finding": "返回了NAICS Code 1114官方描述页面"}
]
```

- 判 **productive** 时：finding说明"哪条新内容推进了哪个缺口"
- 判 **unproductive** 时：finding说明"本轮返回为何与缺口无关"（如"本轮该query返回5条，无一条涉及该缺口"）——弱闸门，防轻判（critic P2-1，落实Kimi约束1完整版"举不出证的unproductive降权"）

**时序语义 + 编号参照物注入（critic P1-2修复）**：

FM prompt 中 `previous_round_info` 改为结构化带编号清单（与验证基准严格一致）：

```
## 上一轮实际执行的补搜query（query_index 必须按此清单，0-based）
[0] vertical farming NAICS code GICS classification official definition
[1] 植物工厂 行业标准 GB/T 农业农村部 定义

## 上一轮发现的缺口（gap_index 必须按此清单，0-based）
[0] 缺少GICS编码归属
[1] 缺少官方定义文件
```

关键点：注入的是**上轮实际执行的query**（去重+预算截断后的 `queries_to_search`），不是FM原始建议（`suggested_queries`）也不是全量seen_queries——消除三套列表不一致导致的索引错位。需新增留存变量 `prev_executed_queries`（每轮补搜后 `prev_executed_queries = queries_to_search`）。

**举证验证函数**（新增 `_validate_yield_evidence`）：

```python
def _validate_yield_evidence(
    yield_evidence: Any,
    prev_executed_queries: list[str],   # 上轮实际执行（验证基准）
    prev_data_gaps: list[str],
) -> bool:
    """验证FM结构化举证有效性。任一条有效即返回True。

    验证规则：
    1. 非数组（含v1.2旧格式字符串）→ 无效
    2. 数组为空 → 无效
    3. 元素非dict / 缺 query_index/gap_index/finding → 该条无效
    4. index 为 bool → 该条无效（bool是int子类，True==1会穿透isinstance检查）
    5. index 非整数或超出范围 → 该条无效
    6. finding 为空字符串 → 该条无效
    """
    if not isinstance(yield_evidence, list) or not yield_evidence:
        return False
    for item in yield_evidence:
        if not isinstance(item, dict):
            continue
        qi, gi = item.get("query_index"), item.get("gap_index")
        finding = item.get("finding", "")
        if isinstance(qi, bool) or isinstance(gi, bool):
            continue
        if not isinstance(qi, int) or not isinstance(gi, int):
            continue
        if qi < 0 or qi >= len(prev_executed_queries):
            continue
        if gi < 0 or gi >= len(prev_data_gaps):
            continue
        if not finding.strip():
            continue
        return True  # 任一条有效
    return False
```

### 3.2 信号2：内容指纹比对（新增 `_content_fingerprint_overlap`）

**指纹构造**：

```python
def _make_fingerprint(item: dict) -> str:
    """单条结果指纹：URL优先，URL为空时fallback到内容前200字符。"""
    url = (item.get("url") or "").strip()
    if url:
        return f"url:{url}"
    content = (item.get("content") or "")[:200]
    return f"content:{hashlib.sha256(content.encode('utf-8')).hexdigest()[:16]}"
```

**重叠判定**：

```python
def _content_fingerprint_overlap(
    round_items: list[dict],            # 本轮全部query的有效结果条目（已过滤搜索失败）
    historical_fingerprints: set[str],  # 此前所有轮次（含首轮静态搜索）的累积指纹集合
    threshold: float,                   # FINGERPRINT_OVERLAP_THRESHOLD，默认0.8
) -> str:
    """重叠率 = 本轮中已存在于历史集合的条目数 / 本轮总条目数（不去重计数：
    同一URL在本轮2个query各返回一次算2条——都返回老页面即无新信息的语义成立）。

    ≥ threshold → 'unproductive'，否则 'productive'。
    本轮无有效条目 → 'productive'（零返回由机械信号负责，职责分离）。
    """
    if not round_items:
        return "productive"
    fps = [_make_fingerprint(r) for r in round_items]
    overlap = sum(1 for fp in fps if fp in historical_fingerprints)
    return "unproductive" if overlap / len(fps) >= threshold else "productive"
```

**过滤规则（critic P2-2）**：计算前剔除 `title == "搜索失败"` 条目（其url为空、content为异常msg，会随机污染重叠率）。

**历史集合**：首轮静态搜索（3个query）指纹在补搜循环前预填充；每轮补搜后并入本轮指纹。内存量级：≤50指纹/run，无问题（critic确认）。

**信号间关系**：信号1是AI判断"有没有新信息"（语义层），信号2是数学判断"搜没搜到新东西"（字节层）。AI可能遗漏（换query但返回同一堆网页），信号2兜底。

### 3.3 信号3：机械信号（v1.2保留，安全网）

### 3.4 仲裁与止损逻辑

**逐信号记录**：

```python

round_signals: list[dict] = []           # 每轮三信号完整组合（FM审查后补全）

prev_executed_queries: list[str] = []    # 上轮实际执行的query（验证基准+prompt注入）
low_yield_trigger_history: list[list] = []  # 逐轮触发信号组合（critic P3-1：不覆盖）

# 第N轮补搜执行后（即时信号）：
valid_items = [r for q in queries_to_search for r in all_results.get(q, []) if r.get("title") != "搜索失败"]
fp_yield = _content_fingerprint_overlap(valid_items, historical_fingerprints, FINGERPRINT_OVERLAP_THRESHOLD)
mech_yield = _mechanical_yield_judgment(queries_to_search, current_results_per_query, seen_queries)
round_partial_signals.append({"round": round_num + 1, "fingerprint": fp_yield, "mechanical": mech_yield})

# 第N+1轮FM审查后（组合判定，插入位置：gaps_closed检查后、budget检查前）：
if round_num > 0 and round_partial_signals:
    prev = round_partial_signals[-1]
    # 信号1：双向举证闸门

    if fm_yield == "productive":
        fm_effective = "productive" if evidence_valid else "unproductive_no_evidence"
    elif fm_yield == "unproductive":
        fm_effective = "unproductive" if evidence_valid else None  # 降权断链
    else:  # null/缺失
        fm_effective = None

    # 三信号OR
    triggered = []
    if fm_effective in ("unproductive", "unproductive_no_evidence"):
        triggered.append("fm")
    if prev["fingerprint"] == "unproductive":
        triggered.append("fingerprint")
    if prev["mechanical"] == "unproductive":
        triggered.append("mechanical")

    round_signals.append({
        "round": round_num,  # 组合判定发生在第round_num+1轮审查，评估的是第round_num轮补搜
        "fm": fm_effective, "fingerprint": prev["fingerprint"], "mechanical": prev["mechanical"],
    })

    # None断链三分支（critic P1-3修复）
    if triggered:
        consecutive_unproductive += 1
        low_yield_trigger_history.append(triggered)
    elif fm_effective is None:
        pass  # 断链：计数不变（FM无法确认且无其他信号触发）
    else:
        consecutive_unproductive = 0
        low_yield_trigger_history.append([])  # 记录空触发以对齐轮次

    if consecutive_unproductive >= 2:
        stop_reason = "low_yield"
        break
```

**为何双向举证（修订#2，对r1"unproductive不设闸门"的推翻）**：r1理由(a)称"误判unproductive后果（多搜一轮）轻于误判productive（漏信息）"——**方向写反了**（critic P2-1）：误判productive的后果才是多搜一轮（约¥0.005+20s）；误判unproductive连续2轮的后果是提前终止补搜+交付物永久缺信息。且v1.2实测FM判unproductive时举证习惯为零（钙钛矿`yield_evidence_history=["","",""]`）。故unproductive也需举证（说明"为何没用"），举证无效降权为断链（不计入不重置）——这落实了Kimi约束1的完整语义（"举不出证的unproductive降权，不计入"）。

### 3.5 影子模式（修订#9，critic P3-7）

**第一次集成实测默认开启**：三信号照常计算并完整记录 `round_signals`，但 `consecutive_unproductive` 不递增（low_yield不触发，照旧budget_exhausted收尾）。

```python
STOP_LOSS_SHADOW_MODE = os.getenv("STOP_LOSS_SHADOW_MODE", "true").lower() == "true"
# 组合判定处：
if triggered and not STOP_LOSS_SHADOW_MODE:
    consecutive_unproductive += 1
    ...
```

**放开条件**（第一次实测后人工核查）：
- 举证验证通过率 > 80%（round_signals中 fm=="unproductive_no_evidence" 占比 < 20%——占比过高说明索引错位或FM不适应结构化举证，是prompt对齐问题而非FM说谎）
- 抽查unproductive判定合理性（对照日志回溯每条补搜结果与缺口的相关性）

**放开方式**：设置 `STOP_LOSS_SHADOW_MODE=false` 重跑实测。
