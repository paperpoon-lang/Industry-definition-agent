## 一、当前状态（v1.3 实测后）

### 1.1 v1.3 已达成（2026-08-17 影子模式5行业实测，可信度★★★★★一手实测）

| 目标 | 结果 |
|------|------|
| FM结构化举证适应 | 10轮组合判定，举证验证通过率100%（0次降权、0次索引错位） |
| 双向举证闸门生效 | FM判unproductive时全部提供有效举证（室内垂直农业/细胞培养肉各1次） |
| 影子审计数据完整 | round_signals/low_yield_trigger_history/fingerprints_sample全量落盘 |
| 成本可控 | 5行业总成本¥1.1381（v1.2为¥1.1345，+0.3%符合"微增"预期） |

### 1.2 v1.3 暴露的根本缺陷（范式问题，非参数问题）

**缺陷：命题不对称导致AI惯性判"有用"，止损机制实质空转。**

- 5行业10轮组合判定，fm信号仅2次判unproductive且不连续，low_yield影子触发0次连续 → 赋权后预期0/5行业止损（实测trace：f028ba8ac96e/128f602bdd7f/908bddd13a78/64f5c78ed6b5/5678dc22f177）
- 根因是逻辑不对称，不是prompt没调好：
  - 判"**有用**"= 存在命题：找到1条"结果推进缺口"的例子即成立，**易证**
  - 判"**没用**"= 全称命题：证明所有结果对所有缺口都没用，**难证**
  - v1.3双向举证闸门加重了不对称：说"有用"随便指一条即可过关（"任一条有效即通过"，[L481-519](file:///Users/paper/trae_project/行业定义agent/demo2/frost_agent.py#L481)验证函数只查格式不查内容）；说"没用"要论证否定性命题
  - **AI的理性策略就是倾向判"有用"**——这是规则设计的必然结果，不是AI的问题

### 1.3 范式对比分析（用户提议的核心洞察）

| 维度 | v1.3（回顾止损） | v1.4（前瞻论证） |
|------|----------------|----------------|
| 默认方向 | 默认继续搜，除非证明"上一轮没用" | **默认不搜，除非给出"下一轮值得搜"的理由** |
| AI需证的命题 | 全称（"全都没用"，难） | 存在（"有缺口+有新方向+可能拿到"，易） |
| 偷懒的后果 | 惯性滑行搜满预算（浪费钱） | 惯性给理由→格式验证通过（r2修正：既有数据预示P≈0）→实质防线是**默认方向反转带来的审计责任+人工抽查**，非机器拦截 |
| 判定时点 | 滞后一轮（浪费已发生，刹车追不回） | 提前一轮（省的是即将发生的整轮搜索） |
| MAX=3下经济价值 | 0（止损与budget同轮触发，v1.3方案§1.3已证） | P(理由给不出)×1轮补搜（审查2理由失败→跳过补搜2+审查3） |

**r2关键澄清（critic P1-1）——机器质检的实际拦截力**：去重是严格相等匹配（`q.strip() not in seen_queries`），而v1.2/v1.3两轮实测中 `query_space_exhausted` **0次触发**（FM同义改写100%穿透）；且5行业trace显示每轮FM的suggested_queries与yield_evidence非空率均100%——与三要素同构的格式输出，**P(给不出有效格式理由)≈0 可从既有数据预判**。因此v1.4的真实拦截力预期趋近零，其确定收益是**审计粒度（每轮搜索有可查的购买理由）+代码简化+范式基础设施**（MAX未来放开后门控点从1变N，经济价值才放大）。§1.3表"偷懒的后果"行已按此修正。

**关键洞察**：命题不对称无法消除（存在永远比全称易证），但**可以把易证的一侧放在"默认停止侧"**。v1.3把易证命题放在放行侧（永远放行）；v1.4把存在命题作为继续的必要条件——AI给理由容易（预期几乎总给），但**每条理由都被落盘审计**，"给不出"时默认停止。拦截不是主要收益，可审计性才是。

## 二、设计目标

**让每一轮补搜都是被"理由"买过来的，而不是被预算惯性推着走的。**

- 每轮补搜（保底轮之后）必须有结构化继续理由：还有缺口 + 有新方向 + 认为可能拿到
- 理由验证零二次验证成本（非空+index合法），真实性由机器质检（去重/指纹）和人工抽查兜底
- 移除v1.3复杂且空转的回顾性机制（fm_effective/三信号OR/None断链/low_yield），净简化代码
- 影子模式先行，用实测数据决定赋权

**价值定位（诚实声明）**：
- 确定收益：审计粒度（每轮搜索有可查的"购买理由"）+ 代码简化（删一个空转机制）+ 刹车逻辑范式修正
- 不确定收益：省钱幅度 = P(理由给不出或质检不过) × ~¥0.03/行业。**r2修正（critic P1-1）：既有数据强烈预示P≈0**（FM格式输出非空率100%+同义改写穿透率100%），经济价值预期趋零；确定收益以审计粒度+代码简化+范式基础设施为主（MAX放开后价值放大，见§九）
- 残留缺口类型分布（r2精确化）：5行业合计17个残留缺口，not_found 9个（52.9%）、snippet_too_shallow 5个（29.4%）、source_tier 3个（17.6%）——not_found+source_tier合计12/17，均为"多搜Tavily无益"型，"停得对"有数据支撑（5行业trace实测，★★★★★）

## 三、v1.4 方案：前瞻继续论证

### 3.0 总体流程

```
首轮静态搜索（3 query）
   ↓
FM审查1：发现缺口？
   ├─ 无缺口 → gaps_closed，结束
   └─ 有缺口 → 补搜1（无条件放行，保底轮内）
        ↓ 搜完（指纹/机械信号采集，审计用）
FM审查2：发现缺口？
   ├─ 无缺口 → gaps_closed，结束
   ├─ 有缺口 + 继续理由有效 + 机器质检通过 → 补搜2
   ├─ 有缺口 + 理由缺失/无效 → no_justification，结束（影子模式下继续并记录）
   └─ 有缺口 + 理由有效但suggested_queries全已试过 → query_space_exhausted，结束
        ↓ 搜完
FM审查3（轮数上限）：发现缺口？→ budget_exhausted / gaps_closed
最终审查 → 残留缺口 + gap_type 路由文案（v1.2逻辑保留）
```

### 3.1 继续理由三要素

**schema**（FM输出新增字段，引用**当前轮**FM自己输出的data_gaps）：

```json
"next_round_justification": [
  {
    "target_gap_index": 0,
    "new_direction": "换标准号定点搜：直接检索GB/T正式发布文本",
    "reachability": "标准号已在搜索结果中出现，全文检索有命中可能"
  }
]
```

三要素语义（来自用户提议）：
- `target_gap_index`：**还有缺口**——针对当前 data_gaps 中哪个缺口（0-based，引用FM本轮自己输出的缺口清单）
- `new_direction`：**有新的方向**——与已试query不同的搜索角度（换英文/标准号/机构名/文件类型）
- `reachability`：**可能拿到**——基于现有信息和分析，为什么认为这个方向搜得到（不是全量证明，只需给出可达性论据）

**验证函数**（新增 `_validate_justification`，改造自v1.3的[_validate_yield_evidence](file:///Users/paper/trae_project/行业定义agent/demo2/frost_agent.py#L469)，复用其六规则防御模式）：

```python
def _validate_justification(
    justification: Any,
    current_data_gaps: list[str],   # 本轮FM自己输出的缺口清单（验证基准）
) -> bool:
    """验证继续理由有效性。任一条有效即返回True。

    验证规则（按用户要求只做两层，不做内容二次验证）：
    1. 非数组（含字符串/None）→ 无效
    2. 数组为空 → 无效（= 给不出理由 → 不支持继续）
    3. 元素非dict / 缺三要素任一 → 该条无效
    4. target_gap_index 为bool/非整数/超界 → 该条无效
    5. new_direction / reachability 为空字符串 → 该条无效
    注：new_direction"是否真的新"不在此验证——由机器质检（§3.3）把关
    """
```

### 3.2 保底轮数

`MIN_GUARANTEED_ROUNDS = 1`（环境变量可调）。

- 第1轮补搜：无条件放行（首轮审查发现缺口即执行）
- 第2轮起（含）：要求有效继续理由才放行

**理由**：第1轮补搜后信息最少，FM的前瞻判断最不可靠（无补搜历史可比对）；给一次免费机会防过早停止。MAX_SUPPLEMENT_ROUNDS=3下实际受理由门控的只有"审查2→补搜2"一个决策点（审查3触发轮数上限），保底轮数=2时门控点为零（退化为v1.2行为），故默认1。

### 3.3 机器质检（新方向主张的验证，零LLM成本）

FM的`new_direction`主张不由代码判断真伪（用户明确不做二次验证），但其**产物**可机器质检：

| 质检项 | 机制（全部v1.3已有，零新增） | 失败处置 |
|--------|------------------------------|---------|
| 新方向=旧query？ | suggested_queries 经 seen_queries 去重后为空 → `query_space_exhausted`（v1.2已有） | 停止（含影子模式，属硬闸门） |
| 新方向产出老内容？ | 指纹信号记录该轮返回与历史重叠率（审计字段，不拦截） | 记录，供下一轮理由可信度人工审计 |

**设计边界**：去重是硬闸门（旧query重复执行是确定性浪费）；指纹是软信号（返回老内容不等于方向错误，可能是搜索源问题）。这与v1.3的角色不同——v1.3中指纹参与止损（空转），v1.4中降为审计。

### 3.6 影子模式（沿用v1.3方法论）

`JUSTIFICATION_SHADOW_MODE=true`（默认，r3改名自STOP_LOSS_SHADOW_MODE）：继续理由照常要求、验证并完整记录，但理由无效时**不拦截**（继续补搜，照旧budget_exhausted收尾）。

**r2澄清（critic P3-1）**：`query_space_exhausted` 在影子模式也拦截——这不是v1.4的语义变更，而是**显式继承**：v1.2/v1.3中该信号本就在影子罩外（影子只罩low_yield计数）。该信号历史上0次触发，无误拦截记录。

**P值测量口径（r2新增，critic P2-1）**：

- **分母 = 到达审查2（即round_num=1）且该轮FM返回data_gaps非空的轮次**。以下不计入分母：①审查1后即终止的行业（gaps_closed/query_space_exhausted/fm_review_failed——未达门控点）；②审查2 FM审查失败的轮次（无理由可评）
- **分子 = 分母中理由验证通过（justification_valid=True）的轮次数**；P = 1 − 分子/分母
- **时序保证**：理由验证发生在query去重判定之前（审查2的FM返回后先验理由、后算去重），故query_space_exhausted硬闸门不污染P值分母

**理由质量抽查标准（r2新增，critic P2-2）**：

- **可信**：reachability引用了具体已见信息（标准号/机构名/URL特征/某条结果标题），new_direction与seen_queries清单对照确为新角度
- **牵强**：三要素非空但reachability无具体引用（如仅写"可能命中"），或new_direction实为已试query的同义改写
- **模板**：多条理由文案高度雷同（如5行业reachability逐字相同）
- **修复触发条件（r3修正，workbuddy脆性评估）**：**≥2条牵强** 或 模板重复≥2次 → 回prompt修复（原"牵强率≥30%"在5-10条样本上是假精度：5条中2条=40%，实际语义即"≥2条"）；修复两轮仍不可信→按§八终止条款处理
- 抽查对象：影子期全部理由逐条核（样本约5-10条，样本小无统计效力，定性判断为主）

**放开条件（阶段一达标后置false）**：理由格式验证机制工作正常 + 抽查无"模板"级问题（"牵强"不阻断放开，记录在案）。

### 13.3 三大结论

**结论1：门控在格式层有效、语义层失明（实测确证§十一 P2风险）**
MAX=5 下出现方向声明"措辞变体"退化：脑机接口连续 5 轮（R1-R5）追同一 YY/T 1987-2025 标准全文、细胞培养肉 4 轮（R2-R5）追 FAO/WHO 报告 PDF、室内垂直农业 3 轮（R3-R5）追 GB/T 4754-2017 PDF——方向声明 bigram 相似度 0.09-0.40，全部低于 0.5 检测阈值。两层验证（非空+index合法）对语义层退化完全失明，但这属已知且接受的设计边界（§3.1显式不做内容二次验证），非实现缺陷。

**结论2：预算不是绑定约束——语义主题三类不变，gap_type 占比向"离墙更近"迁移**
补搜 2→4 轮，残留缺口 19→20 个（缺口数不降反微升，缺口 churn 属 FM 行为波动）。缺口语义主题仍集中三类：GICS/NAICS 国际分类归属、GB/T 等标准全文、监管一手文件；但 gap_type 构成显著迁移：not_found 42%→30%、snippet_too_shallow 26%→**60%**、source_tier 32%→**10%**——预算改变的是缺口的"离墙距离"而非"墙的存在"：多轮搜索把缺口从"不知道有没有"推进到"标准号已知但全文拿不到"（snippet_too_shallow 集中），反而强化结论 3。R3-R5 的边际产出是**缺口坐标化**：挖出 GB/T 45177-2024《人工光型植物工厂光环境技术规范》（垂直农业）、YY/T 1987-2025 十二类术语名（脑机接口）、GB/T 43568-2026 与"<5%"阈值两种表述冲突（固态电池）、NB/T 11735-2024/11736-2024（钙钛矿）。标准号级情报已落盘 Event Log，是未来搜索源升级的精确输入——但报告生成需要定义**内容**，标准号本身进不了报告。多花 2 轮买坐标不买闭合。

**结论3：信息不可达与实测一致——Tavily 片段级搜索对全文级需求的结构性边界（n=5 单跑，方向性结论）**
Tavily 能证明信息**存在**（标准号/文号/机构均搜到），给不了**全文内容**。多轮搜索的天花板 = 把缺口定位到精确坐标后停在墙前。MAX=3 残留缺口逐条分类（明细见§13.6附录，单人定性分类★★★☆☆无交叉验证）：16/19≈84%属结构性拿不到（官方全文/一手文件/公开渠道无答案），3/19≈16%属预算/方向可覆盖。

### 13.4 r3 两个观测项结论（workbuddy建议①②）

- **承诺效应（①）**：成立。MAX=3 赋权实测 20 个补搜 query（5行业×2轮×2query）中 2 个高相似（bigram≥0.6），但均为具体化深挖（脑机接口 R2 加 NAICS 具体编码段 334510/339112、垂直农业 R2 从 NAICS 换 GICS 定向），与 FM 声明的 new_direction 一致；纯同义改写 0 例；方向声明跨轮相似度全部≤0.39。
- **gap_type 确定性门控对照（②）**：两口径均证伪。严格口径（本轮缺口全为 snippet_too_shallow/source_tier 才停）5行业全程不停（每轮都有 not_found 缺口，形同虚设）；宽口径（全为三种非直接可闭合类型即停）5行业全部 R1 即停（等于保底轮后必停，误杀一半补搜）。确定性规则优于 FM 论证路径的假设不成立，对照数据封存。

### 13.5 封存条款

**v1.4 为补搜停止逻辑线的终版，不再迭代。**重启条件（满足其一即重开评估）：

1. `MAX_SUPPLEMENT_ROUNDS` 默认值放开（>3）进入生产配置——届时语义层退化（结论1）从无害变有害（门控点=MAX−2 个），需先解决方向声明语义查重（候选方案：new_direction 与历史方向的 embedding 相似度机器比对——判定方非 FM 自评，不违背 v1.4 设计原则；届时需先补延迟基线，本次实测未测延迟维度）；
2. 阶段三搜索源升级落地（非片段级源接入：官方标准平台/SEC/学术库等）——届时缺口坐标系（结论2的Event Log数据）直接复用；
3. `LLM_MODEL` 或 `FM_REVIEW_PROMPT` 发生变更——P=0 前提建立在当前模型×当前 prompt 的行为特性上，换模型/prompt 后理由给出率与格式遵循度未知，需重跑 5 行业影子实测确认；
4. 业务行业类型显著偏离标准密集型硬科技（如消费品/服务业占比上升）——残留缺口分布假设（§13.6）失效，需重估。

默认值维持 MAX=3。reachability 语义查重现阶段不做——真权衡是 MAX=3 下门控点仅 1 个（保底轮后首查），拦截收益趋零，不值得增加机制复杂度；MAX 放开后按重启条件 1 连带评估。B1-2 迭代线（v1.0→v1.4）就此关闭。
